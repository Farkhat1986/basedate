# Тестирование WordPress Posts API (CRUD операции)

Набор тест-кейсов для тестирования CRUD операций с пользователями через WordPress REST API.

## Общая информация

**Базовый URL:** `http://localhost:8000/wp-json/wp/v2/posts`  
**Аутентификация:** Требуются права администратора

# Тест кейсы CRUD операций

## Тест кейс 1: Проверка создания нового поста через API (с аутентификацией)

**Цель:** Создание поста авторизованным пользователем

**Шаги:** 

1. Отправить POST запрос на адресс http://localhost:8000/wp-json/wp/v2/posts

2. Указать в заголовках Basic-Auth с логином и паролем ("Firstname.LastName", "123-Test")

3. Тело запроса (JSON) 

```
		{
			"title": "Тест пост",
			"content": "Содержимое поста",
			"status": "publish"
		}
```

**Ожидаемый результат:** 

- Статус 201 created
- В теле ответа:

    - id - целое число, 
    -  title.rendered = "Тест пост", 
    - content.rendered = "Содержание поста", 
	- status = publish, 
	- пост сохранен в таблице wp_post:
		* post_type = 'post'
		* post_status = 'publish'

## Тест кейс 2: Проверка получения поста по ID

**Предусловие: Создан пост по Тест кейсу 1, его ID = post_id**

**Цель:** Получение поста по его ID

**Шаги:**
	1. Создать пост (из Тест кейса 1), по его ID
	2. Отправить GET запрос http://localhost:8000/wp-json/wp/v2/posts/{post_id}

**Ожидаемый результат:** 
	
* Cтатус ответа 200 ОК, 
* В теле ответа:
	- id = post_id,
	- title.rendered = title.rendered указанные в {post_id},
	- content.rendered = content.rendered указанныев {post_id}
	- status = "publish"

## Тест кейс 3: Проверка получения списка всех постов

**Предусловие:** В системе существует как минимум 2 опубликованных поста

**Цель:** Получение списка всех постов

**Шаги:** 
	1. Отправить GET запрос http://localhost:8000/wp-json/wp/v2/posts

**Ожидаемый результат:** 
* Статус кода 200 ОК, 
* Тело ответа массив из объектов, 
* Каждый объект содержит:
	-  id = целое число, 
	- title.rendered - непустая строка, 
	- content.rendered - непустая строка,  
	- status = "publish"
	- link - валидный URL

## Тест кейс 4: Проверка обновления существующего поста

**Предусловие:** Создан пост по Тест кейсу 1, его ID = post_id

**Цель:** Получение обновленных данных существующего поста

**Шаги:**

1. Создать пост
2. Отправить POST запрос  запрос http://localhost:8000/wp-json/wp/v2/posts/{post_id}, где post_id - это id целевого поста
3. В заголовках указать Basic Auth = "Firstname.LastName" / "123-Test"
4. Тело запроса JSON
```
		{
			"title": "Обновление заголовка",
			"content": "Новое содержимое обновленного поста"
		}	
```

**Ожидаемый результат:** 
* Статус 200 ОК, 
* title.rendered - "Обновленный заголовок",
* content.rendered - "Новое содержимое обновлённого поста"
* В БД wp_post:
	- post_title - "Обновление заголовка"
	- post_content - "Новое содержимое обновленного поста"

## Тест кейс 5: Проверка удаления поста

**Предусловие:** Создан пост по Тест кейсу 1, его ID = post_id

**Цель:** Получение данных об удалении поста 

**Шаги:**

1. Отправить DELETE запрос http://localhost:8000/wp-json/wp/v2/posts/{post_id}, где post_id - это id целевого поста 
2. В заголовках указать Basic Auth = "Firstname.LastName" / "123-Test"

**Ожидаемый результат:** 

1. Статус 200 ОК, 

2.  В теле ответа status = "trash"

3.  В БД wp_post:
	- запись с ID = post_id имеет post_status = "trash" для ID
