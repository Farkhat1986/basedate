**Базовый URL:** `http://localhost:8000/wp-json/wp/v2/`  
**Аутентификация:** Требуются права администратора

# Тест кейсы

## Тест кейс 1: Проверка получения поста со статусом “draft”

**Предусловие:** Создать пост напрямую в БД с post_status = 'draft', post_type = 'post'

**Цель:** Убедиться, что черновой пост (draft) не возвращается в общем списке опубликованных постов

**Шаги:** 

1. Отправить GET-запрос /wp-json/wp/v2/posts

2. Проверить, что пост с этим ID отсутствует в списке

3. Отправить GET-запрос /wp-json/wp/v2/posts/{post_id} 


**Ожидаемый результат:** 

- Ответ для /posts не содержит этот пост
- Ответ для /posts/{id} возвращает 404 Not Found (если нет авторизации)

**Очистка:**

- Удалить пост из БД

## Тест кейс 2: Проверка получения поста со статусом “private”

**Предусловие:** Создать пост напрямую в БД с post_status = 'private'

**Цель:** Проверить, что приватный пост недоступен неавторизованному пользователю

**Шаги:**
	1. Отправить GET /wp-json/wp/v2/posts/{post_id} без авторизации
	2. Проверить статус-код 401 Unauthorized или 404 Not Found
	3. Отправить тот же запрос, но с Basic Auth (валидный пользователь)

**Ожидаемый результат:** 
	
* Без авторизации — пост недоступен
* С авторизацией — возвращается корректный пост (поля совпадают с БД)

**Очистка:** Удалить пост

## Тест кейс 3: Проверка получения запланированного поста (“future”)

**Предусловие:** Создать пост напрямую в БД с post_status = 'future' и post_date в будущем

**Цель:** Проверить, что пост со статусом future недоступен до публикации

**Шаги:** 
	1. Отправить GET /wp-json/wp/v2/posts
	2. Проверить, что запланированный пост не отображается в списке
	3. Отправить GET /wp-json/wp/v2/posts/{post_id}

**Ожидаемый результат:** 
* Статус 404 Not Found для неавторизованных
* При авторизации (админ) — пост возвращается

**Ожидаемый результат:** Удалить комментарий и пост

**Очистка:** Удалить пост

## Тест кейс 4: Проверка получения комментария, не прошедшего модерацию

**Предусловие:** 
* Создать пост в БД
* Создать комментарий с comment_approved = '0'

**Цель:** Проверить, что комментарий с comment_approved = '0' не отображается в списке публичных комментариев

**Шаги:**

1. Отправить GET /wp-json/wp/v2/comments?post={post_id}
2. Проверить, что созданный комментарий отсутствует
3. Изменить comment_approved = '1' и повторить запрос

**Ожидаемый результат:** 
* До одобрения — комментария нет в ответе
* После одобрения — появляется

**Очистка:** Удалить комментарии и пост

## Тест кейс 5: Проверка получения комментария, привязанного к несуществующему посту

**Предусловие:** Создать комментарий напрямую в БД с comment_post_ID = 999 (пост не существует)

**Цель:** Проверить корректную обработку комментария с некорректной связью (битая FK) 

**Шаги:**

1. Отправить GET /wp-json/wp/v2/comments/{comment_id}

**Ожидаемый результат:** 

1. API возвращает корректный объект комментария (WordPress не проверяет связь при выдаче) 

2.  Поле post ссылается на несуществующий ID

**Очистка:** Удалить комментарий

## Тест кейс 6: Проверка видимости чернового поста для владельца

**Предусловие:** 
* Создать пост напрямую в БД с post_status = 'draft'
* Привязать его к определённому пользователю в поле post_author

**Цель:** Проверить, что черновой пост виден владельцу этого поста, несмотря на его статус draft 

**Шаги:**

1. Отправить GET запрос /wp-json/wp/v2/posts/{post_id} для авторизованного пользователя, который является владельцем этого поста
2. Проверить, что статус ответа 200 OK
3. Убедиться, что в теле ответа присутствуют все поля поста (id, title.rendered, content.rendered), а также что статус этого поста равен 'draft'

**Ожидаемый результат:** 

1. Статус ответа 200 OK
2.  Данные поста возвращаются, статус этого поста — 'draft'
3. Это подтверждает, что автор может видеть свой черновик, даже если он не опубликован

**Очистка:** Удалить пост из БД
